# FAILURES

Bugs, dead ends, and what we learned. One short entry each, newest at the bottom.

- 14:13 `git init -b main` ran on a repo someone had just initialised (branch `master`, remote set). It printed "re-init: ignored --initial-branch". Fixed with `git branch -m master main` before the first commit.
- 14:15 The fixture generator wrote `disamb or [] if abstain else []`, which Python parses as `disamb or ([] if ...)`. Caught on read-through and parenthesised before the first run.
- 14:33 `core.autocrlf` is on for this machine, so a checkout would turn `sse_sample.txt` into CRLF and break the SSE wire format. `.gitattributes` pins fixtures to LF.
- 14:24 [Lane A] Bash heredocs containing both quote styles failed in this shell ("unexpected EOF while looking for matching quote"). Switched to the Write tool for Python files.
- 14:33 [Lane A] Two store tests were wrong, not the code: the SSE throttle fills its 20 slots with non-info events once alerts run out, and the 15 min window is measured from the newest event (08:49:59.7), not from a round minute.
- 14:36 [Lane A] Live smoke test showed "analyze failed: NotImplementedError" logged every second while Lane B is not merged. Now logged once per distinct error.
- 14:30 [Lane B] First run on the hero fixture labelled every victim latency_spike: latency z-scores cap at 50 while error_rate z is about 30, so "biggest z wins" always picked latency. Fixed with an explicit errors-dominate rule (error_rate >= 0.25).
- 14:33 [Lane B] Synthetic ambiguous scenario opened as postgres (0.6) on 2 of 8 seeds: when postgres lock waits crossed the threshold before the gateway, postgres gained 0.1 precedence and the margin reached 0.167. The scenario is defined as "postgres crosses last", so the builder now places it more than one scrape after the gateway. Lesson: the abstain case is fragile to scrape phase, which is exactly what the disambiguation list says.
- 14:36 [Lane B] 20k-event timing swung from 70 ms to 550 ms between runs because other lanes were using the CPU. Added a cached minute-prefix fast path to timestamp parsing and a single preprocessing pass. Typical run is now 70 to 250 ms; the test asserts < 1 s.
- 14:40 [Lane B] Incremental replay of Lane A's red_herring showed a one-second ghost "api-gateway: latency_spike" incident before the merge into the postgres incident (the gateway alert lands before intermediate services are confirmed). Fixed with the 3 s settle rule for single-service incidents.
- 14:44 [Lane B] Concurrent faults that share api-gateway (redis_down + bad_deploy, psp_slow + redis_down) merge into one incident, because the gateway is anomalous and adjacent to both sides. This follows the induced-subgraph grouping rule; the root is still one of the two real causes, but the second cause shows only as a high candidate. Not fixed (demo resets between faults).
- 14:44 [Lane B] If a fault stays active longer than the store window (15 min), its pre-fault baseline is evicted, onsets slide with the window, and the incident id changes every recompute. Engine cannot fix this without history; the store should keep the window above fault duration or the demo should reset.
- 14:42 [Lane C] The first browser check was on a 1536 px viewport (125% Windows scaling) and the 1920 px layout wrapped the top bar. Fixed by zooming a 1920 px design canvas to the window width; React Flow needed a remount keyed on the zoom so fitView ran at the final size.
- 14:42 [Lane C] Running a second fault in fixture mode mixed old and new restamped metrics, so the sparkline zig-zagged. The fault action now clears the event buffer in fixture mode only.
- 14:42 [Lane C] A mock SSE server that closes the stream showed EventSource replaying the same events on reconnect. The reducer now drops events whose id is already in the buffer, which also avoids duplicate React keys in the storm feed.
- 14:42 [Lane C] `next dev` refuses to start a second server from the same app directory ("Another next dev server is already running"), so the live-mode check needed the fixture server stopped first.
- 14:55 [integration] `gen_fixtures.py` wrote fixtures with Windows CRLF, because `Path.write_text` is in text mode, so `sse_sample.txt` had `\r\n` SSE framing on disk. Tests missed it because Python normalises line endings on read. Fixed with `newline="\n"`.
- ~15:10 [integration] In this shell tooling, a backslash escape inside a heredoc or sed replacement (for example `\n`) can be turned into a real newline, which broke `gen_fixtures.py` twice. Workaround: build the character with `chr(92)` in Python. Lane D hit the same issue with `—`.
- 15:26 [integration] Contract drift caught after the fixture regeneration: 5 tests failed. Three hard-coded the old id `inc_1`, and now read it from the fixture. The report fixture cited hand-picked events that the engine never put in its evidence set; its sentences are now derived from the engine's own timeline. The `sse_sample.txt` topology_state came from a second copy of the health logic, and now comes from `app.store.build_topology_state`. Lesson: any fixture built by a hand-written copy of production logic will drift.
- 14:26 [Lane D] Every narrate() call took ~1.5 s even with no keys and a mock transport: building httpx's SSL context is slow on Windows, and it ate into the 8 s LLM budget. Fixed by skipping the client entirely when no key is set and building the SSL context once (warmed in make_router when a key exists).
- 14:31 [Lane D] The Write tool and shell heredocs turned `\u2014` escapes into literal em dashes in the narrator source and tests. Fixed by rewriting them with `chr(92) + "u2014"` so no source file contains a literal em dash. Lesson: grep for U+2014 after every write, not just in docs.
- 14:44 [integration] The Groq model in CLAUDE.md (`llama-3.3-70b-versatile`) is no longer served on our key (404 model_not_found). Mocked tests could not catch this; only a live call did. Switched to gpt-oss-120b.
- 14:37 [integration] `backend/requirements.txt` pinned fastapi 0.115.* but the venv had 0.162 (starlette 1.10, sse-starlette 3.7), so Render would have run an untested stack. Pins move to the tested versions in the A+B merge.
- 15:41 [integration] The narrator's default incident getter imported the `app.store` module and looked for `get_incident` or `incidents` on it, but Lane A keeps incidents on the `store` instance. Every report would have returned 404, and the `try/except ImportError` in main.py hid the problem. Caught on read-through before merge.
- 15:41 [integration] A known limit of citation grounding: in a live Groq report, one sentence said ledger-svc errors "led to" auth-svc failures. auth-svc does not call ledger-svc; both depend on postgres. Every cite was valid, so grounding kept it. Grounding checks that evidence exists, not causal claims. A possible fix is to drop sentences that assert causation between services with no edge between them.
- 15:53 [upgrades] The naive prompt with every non-info event (including about 400 failed-request events) got HTTP 413 Payload Too Large from Groq. Both the naive mode and the LLM eval baseline need a size-bounded compact dump; the fixture used non-request events capped at 150 lines. Lane H owns the final format, and it must be identical for U3 and U4.
- 16:00 [Lane H] First live naive smoke on events_db_pool (811 events -> 150 lines, 13.5 KB prompt): Groq answered postgres in 6.9 s, including the one-off ~1.5 s Windows SSL setup. That is too slow for the 8 s narrator budget, so the naive path has its own 20 s budget instead of sharing the narrator's.
- 16:11 [integration] The Groq key's limit is 8,000 tokens per minute. One naive call (about 4k tokens) followed by a narrator call in the same minute returned an HTTP error, likely a 429, so the report fell back to Gemini; the guardrail still dropped 1 uncited sentence. Consequence: the eval's llm_only baseline cannot run on 100 runs in time (about 50 min). It runs on a stated fixed subset with pacing, and RESULTS.md reports its n.
- 16:15 [Lane F] `test_narrate.py::test_hang_respects_total_budget` failed once in a full-suite run while other lanes were loading the machine (suite took 39 s instead of 16 s); it passes alone and on the rerun. A timing test, not an engine bug.
- 16:13 [Lane I] The case study's table figures overflowed at 375 px: the class name `table` on `<figure>` also matched Tailwind v4's `table` utility (display: table), which the root globals generate once any scanned source contains the word. Renamed to `tbl`/`fig` and set `figure { display: block }` under `.cs`. Lesson: in a Tailwind app, scoped class names still collide with utilities; avoid bare utility words.

Fixed: the eval removes the Gemini key for those calls, paces at about 32 s per call, retries Groq, and reports failed runs in the split text.
